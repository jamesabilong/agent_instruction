## Changes

Returning to All removes the filter. Accessible history filter names make the browser regression independent of select ordering.
- **Database suite isolation:** backend Vitest disables file parallelism whenever either database gate is enabled. `test:integration:db` enables both gates and runs the complete integration directories, including the budget checks and FP-65 rollback/reapply. Ordinary unit runs retain parallelism. No application schema changes were needed.
- **Current report provenance:** every runner invocation gets an execution ID before validation, dependency checks or database setup. Artifacts are under `testing/reports/runs/<execution-id>/<group>/`. `latest-run.json` tracks mode and lifecycle, and the report command checks it before selecting a matching artifact. Invalid arguments, setup failure, interrupted/in-progress runs, listing/generation previews and omitted groups cannot expose a prior success as current. Current failed-test reports remain accessible. Frontend and testing report commands use the same guard.
- **Role-specific authentication:** FP-65 feature helpers capture the actual `freshprice_session` cookie. Each captured identity is verified through `/auth/me` in an independent request context. The permission case also retains an operator cookie, logs in as a member, and proves both captured identities still authorize as their original roles.
- **Loaded whole-app assertions:** the navigation case creates its own persisted member post/tag. Search and shopping must show the seeded Ginger product; contact must show its contact heading and mail link; community/profile must show that member's actual post and profile identity; moderation must show its controls, post and tag. Each final protected URL is checked.
