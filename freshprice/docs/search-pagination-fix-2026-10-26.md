# Search pagination fixes — local verification, October 26, 2026

Fixed both UI gaps found by the [populated browser audit](populated-browser-verification-2026-10-26.md): PhilWatch can navigate all search result pages, and FreshPrice product-name search filters the full price set before pagination. These are local working changes in three app repositories; application publication/release remains pending. Only agent documentation is authorized for publication in this task. Production was not seeded, queried or changed; exemptions remain disabled.

[Sanitized verification evidence](../evidence/search-pagination-fix-2026-10-26.json).

## Behavior and implementation

- PhilWatch `/search?q=...&page=...` requests the page and retains API metadata. Previous/Next links preserve encoded queries and expose boundary states plus the page/total count. Submitting a changed query starts at page one. Repeated parameters use their first value; invalid/nonpositive/noninteger/unsafe pages fall back to one. Pages beyond the current result set redirect to its last page (or page one for no results), recovering when content changes between requests.
- The server-only search helper retains its restricted content-reader path. An API failure produces a visible search error rather than a successful empty result. Category/detail helpers and the article association/query implementation were not changed.
- Current-price API `GET /api/freshprice/market-prices?q=...` accepts a trimmed string of at most 200 characters. It searches product **name**, case-insensitively, with literal substring semantics for `%`, `_`, backslash and quoted text. The product join is filtered before both COUNT and LIMIT/OFFSET; product/market/unit filters combine with search. Blank/absent queries retain existing behavior, envelopes and unique row ordering.
- The shared public/admin price list sends `q`, resets to page one on query/filter changes and renders the API's rows/counts in desktop and mobile views. Query persists during page navigation and refresh; clearing it restores unfiltered results. Existing stale-response protection in the hook remains intact. The UI bounds input to 200 characters.
