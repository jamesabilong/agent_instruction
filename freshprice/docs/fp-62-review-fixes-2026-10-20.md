## Behavior

- The editor stays mounted after its first disclosure opening, so collapse/reopen retains the full draft and an in-flight submission. Product/account keys still reset private composing state; signing out unmounts it. This is in-memory form retention, not durable offline storage.
- Operators can explicitly retract an approved variant after confirming its exact source revision. A retraction preserves content, source, author, original reviewer and approval history, recording a separate private retraction actor/time. It excludes that variant from public notes, seasonal browsing and current-variant counts without changing the canonical wiki or other variants. Repeated retraction is safe; stale superseded or pending entries cannot be retracted. Approval/rejection still applies only to pending proposals. Author name withdrawal remains name-only; author cancellation is separate future workflow work.
- The client captures a UUID submission identity and normalized proposal once per operation. An uncertain response freezes editing and offers an explicit same-operation retry, including after collapse; confirmed success resets the form and allocates a fresh identity for a deliberate next proposal. Definitive validation/auth/conflict errors release the identity for correction. Account/product changes clear the editor.
- The server serializes each submission UUID with a PostgreSQL transaction advisory lock, validates the original author/product/normalized payload hash and returns the existing row on matching retries. Conflicting reuse returns 409. Replay resolves before checking current source publication/revision, so an intervening source change or moderation decision does not duplicate or republish the original proposal, and replay cannot restore withdrawn credit. Public output excludes the hash and private review/retraction identities. Older clients without submissionId retain their previous random-ID behavior; retry safety applies to identity-bearing requests.
