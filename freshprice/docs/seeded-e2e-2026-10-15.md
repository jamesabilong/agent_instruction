## Ticket selection and local fixtures

`testing/lib/ticket-e2e-scope.mjs` registers each ticket’s exact spec files, expected scenario count and fixture-requirements JSON. The branch must identify exactly one ticket; both app checkouts must target the same ticket. FP-65 registers two isolated groups: nine observation feature scenarios and 30 whole-app scenarios, temporarily assigned to FP-65 at the user's request. Default execution runs both (39 cases), each against a fresh database. Use `--suite=feature` or `--suite=whole-app` to select one complete group. Legacy suites run only through explicit legacy commands. Unknown/mismatched branches and scope filters fail before database setup. The whole-app coverage mapping and fixture details are in `testing/tickets/FP-65/whole-app/COVERAGE.md`.

No maintained ticket seeder belongs in an app repository. `testing/lib/generate-seeder.mjs` reads the ticket’s JSON requirements and generates `testing/.local/seeders/<TICKET>-<group>.mjs`. Generation alone never connects to a database. Every full run regenerates that script, creates a disposable PostgreSQL container, applies real migrations, runs the guarded transactional seed, then starts real API/frontend servers. The seed accepts only the exact runner-local test database/port and refuses nonempty fixture tables. Normal pass/failure cleanup removes only the runner-owned container/volumes.

Fixtures provide synthetic password-hashed operator/member accounts, Ginger/Luya/Luy-a, Muscovado, two Cebu markets and official ₱42 current / ₱40 historical prices. These are test requirements, not claims about current market prices. The E2E scenarios create observations and additional workflow data through the real UI/API. The lost-response scenario aborts delivery only after the real import commits, then checks same-batch replay and stored counts.

All testing-folder files are local and outside app Git repositories. Its `.gitignore` excludes `.local`, reports and the dependency link if separately versioned later. The earlier unpushed backend seeder-only commit was removed with explicit user approval; existing backend work was preserved. Nothing was pushed. The repository-seeded CI workflow was removed because a remote checkout cannot rely on this unpushed local folder. Original manual test workflows are archived under `testing/legacy/ci`; app build/deployment workflows remain unchanged.

## Execution and acceptance mapping

One worker, no retries, no fail-fast and no focused tests. The completion reporter rejects skipped, missing and failing scenarios, including expected failures. `--list` is only a scope preview; `--generate-seeder` only prepares a local script. Neither counts as a successful E2E execution. Reports and traces live under `testing/reports`.
