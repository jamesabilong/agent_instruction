## P2 — Clearing the corrected product causes a render loop

Location: `fresh-price-front/src/features/admin/price/ObservationManager.tsx:62`.

1. Open Price History → Manage observations → Correct / exclude.
2. Click Change on the selected Corrected product.
3. The callback converts the empty selection to numeric `0`; the control receives the truthy string `"0"`.
4. `SearchableProductSelect` sees an unknown selected ID and calls `onChange("")` in its effect. The inline callback creates another editing-state object with zero, changes callback identity and triggers the effect again, indefinitely.

Reproduced with the real shared picker and ObservationManager in React Testing Library. Captured the Maximum update depth warning and stopped the loop via the test boundary. Existing browser correction coverage only changes exclusion, so it misses changing the product.

Fix requirement: preserve an empty picker value when productId is unset (or keep draft product IDs as strings), and ensure clearing/choosing a replacement product terminates without repeated state updates. Add a regression covering Change → search → choose → save.

## P2 — A soft-deleted market crashes observation management

Locations: `platform-backend/src/apps/freshprice/services/priceObservationService.js:79` and `fresh-price-front/src/features/admin/price/ObservationManager.tsx:54`.

Markets use Sequelize paranoid deletion, and the normal market delete service calls `market.destroy()` without force. The observation FK cascade only applies to hard deletion. The observation-list query keeps the quote via an optional market join, but its default paranoid association returns `market: null`. The UI unconditionally reads `row.market.name` and crashes the whole management list. The public trend query also retains the old quote with a blank market name; handling of archived market history needs to be explicit.

Reproduced against migrated disposable PostgreSQL 14: import a quote, perform normal soft deletion, list observations → one retained quote with null market. Separately rendered that exact API shape through ObservationManager and captured the null-property rendering failure.

Fix requirement: deliberately handle archived market associations in admin reads (for example include archived markets with an explicit label), use nullable-safe rendering/types, and keep correction/exclusion of retained quotes possible without silently reassigning their market. Public historical comparisons should retain meaningful market identity or apply an explicit eligibility rule. Add a real database and UI regression for market deletion after import.
